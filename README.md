# Chronicle Forge — цех кампаний

Репозиторий производства **пяти полноценных мини-кампаний** для движка
**Chronicle Forge**. Движок закрыт и здесь не лежит: контент полностью
отделён от движка. Каждая кампания — самостоятельный пакет
(`campaign.json`, `world.json`, `manifest.json`, модули и медиа) и попадает
в `main` только после полного ревью.

## Роли и доступы

| Роль | Зона ответственности | Доступ |
| --- | --- | --- |
| **Producer** | продукт целиком: очередь, приёмка, мерж кампаний в `main` | ревью + мерж |
| **Technical Game Designer ×5** (TGD-1 … TGD-5) | одна кампания целиком: документ → контент → медиа → самоаудит → PR | своя ветка `campaign/<слаг>` |
| **QA Engineer** | аудит кампаний: структура, ссылки, баланс, тексты, логика сюжета | чтение всех веток + ревью |
| **Technical Director** (TD) | связка с движком: выдача задания и ID кампании, проверка запуска, финальный апрув, отчёт о пробелах чемодана | закрытый движок + этот репозиторий |
| **Координатор** | эстафета между ролями, очередь, маршрутизация вопросов, эскалации | оба репозитория |

- Роли закреплены: у каждой кампании свой TGD.
- **Одна роль за раз**: в один момент времени работает один агент, эстафету
  передаёт Координатор.
- **Одна кампания за раз**: следующая начинается только после того, как
  предыдущая прошла все гейты и влита в `main`.

## Линейка и очередь

| № | Кампания | Жанр | Витрина механик | Папка |
| --- | --- | --- | --- | --- |
| 1 | «Ночной перевал» | выживание в дикой местности | потребности, статусы, лагерь, преследование, дедлайн, permadeath | `campaigns/01-night-pass` |
| 2 | «Пепельные списки» | аренный турнир | гекс-бой, крафт и ремонт, отряд, прогрессия, удача, NG+ и метапрогресс | `campaigns/02-ash-lists` |
| 3 | «Караван трёх дорог» | экономический роуд-трип | карта и путешествия, валюты и обмен, цены, фракции, кодекс, стадийные квесты | `campaigns/03-caravan` |
| 4 | «Кабинет снов» | спиритический детектив | катсцены, состояния сцен и слои, магия и рассудок, продвинутые диалоги, тема | `campaigns/04-dream-cabinet` |

## Маршрут кампании

| Этап | Кто | Результат |
| --- | --- | --- |
| 0. Задание | TD | в движке создаётся кампания (ID назначает движок), задание с брифом и ID кладётся в `campaigns/<слаг>/TASK.md` |
| 1. Дизайн-документ | TGD | `design_doc` по бланку `__chronicle_ai__/design-template.md` — заполняется **до** контента и обновляется на каждой итерации |
| 2. Производство | TGD | ветка `campaign/<слаг>`, пакет по гайду, коммит и пуш каждые 15 минут |
| 3. Самоаудит | TGD | `node __chronicle_ai__/campaign-audit.mjs campaigns/<слаг>` — без ERROR |
| 4. PR | TGD | описание по шаблону, чеклист ниже, блок `cf-feedback` |
| 5. Ревью | QA → TD → Producer | три вердикта: аудит / запуск / приёмка. Правки — в ту же ветку |
| 6. Мерж | Producer | PR влит в `main`; ветка остаётся как история |
| 7. Релиз | TD | сборка `.chronicle` для игроков |

- **QA** ведёт аудит: структура и ссылки (headless-аудит), баланс по цифрам,
  тексты и логика сюжета, непротиворечивость. Динамический плейтест — не его
  зона.
- **TD** импортирует `.chronicle` в движок и проходит вступление и ключевые
  маршруты: кампания обязана запускаться и играться без падений. Все
  замечания TD (включая пробелы чемодана) фиксируются в Notion.
- Возврат на доработку — нормальный цикл. Если кругов правок больше двух
  подряд, Координатор эскалирует вопрос мастерам.

## Правила (обязательные)

1. **ID кампании не создаётся агентом.** ID назначает движок, он лежит в
   `TASK.md`. Не придумывать, не менять, не переиспользовать id сущностей:
   «устаревшее» удаляется и создаётся заново.
2. **Интернета в песочнице нет.** Никаких внешних сайтов и загрузок. Работай
   тем, что есть: файлы, код, генерация изображений, синтез голоса, git
   этого репозитория.
3. **Коммит и пуш каждые 15 минут** реального времени: песочница
   сбрасывается, незапушенное теряется. Инструменты разработки храни в папке
   кампании (`tools/`) и пушь вместе с ней.
4. **Контент отделён от движка.** Файлы движка не редактируются и не
   копируются сюда. Механики не выдумываются: чего нет в гайде — в блок
   `cf-feedback`, а не «через флаги».
5. **Медиа — только файлами внутри пакета**, относительные пути. Важный
   контент не живёт по временной внешней ссылке.
6. **Лицензии:** у каждого взятого файла — источник и лицензия в
   `attribution` кампании. Права не выдумываются.
7. **Тексты на русском, id — латиницей** с префиксом секции (`scene_`,
   `npc_`, `item_`, `quest_`…). ID кампании — только из задания.
8. **Системный интерфейс не трогаем**: надписи кнопок и состав меню меняет
   только движок; кампания настраивает `title`, `description` и данные темы
   по гайду.

## Медиа и квоты

- **Квоты песочницы: 10 изображений и 10 озвучек за ход.** Ход не
  закрывается, пока квота не отработана, если генерировать есть что;
  генерация ради генерации запрещена.
- **Графика** — сгенерированные изображения. Прозрачные роли (эмблема меню,
  спрайты сцен, фигурки боя) — PNG с альфа-каналом; хромакей —
  `cutout-chromakey.py`, результат обязательно осмотреть глазами.
- **Озвучка** — реальный голос: интро, катсцены, ключевые реплики.
- **Музыка и звуки** — только реальные файлы из библиотеки `library/`
  (наполняет TD). Синтезированные заглушки не подставляем; если нужного
  звука нет — запрос, а не подмена.
- Порядок работы по пирамиде приоритетов: критический каркас → атмосфера →
  сюжет → полировка.

## Структура репозитория

```
__chronicle_ai__/   чемодан: campaign-guide.md, campaign.schema.json,
                    design-template.md, campaign-audit.mjs, cutout-chromakey.py
library/            реальные медиа-исходники (music/, sfx/, fonts/) + CREDITS.md
campaigns/
  01-night-pass/          корень Campaign Package — уходит в .chronicle
    campaign.json  world.json  manifest.json
    scenes/  dialogues/  entities/  quests/  rules/  recipes/
    codex/  cutscenes/  encounters/  arenas/  assets/
    TASK.md               задание с ID (в релиз не входит)
    tools/                инструменты TGD (в релиз не входит)
```

- Из папки кампании в релизный `.chronicle` не попадают `TASK.md` и `tools/`.
- Выбранные из `library/` файлы копируются в `assets/` своей кампании —
  пакет остаётся самодостаточным.
- Готовые кампании лежат в `main`; новая ветвится от `main` и может
  переиспользовать ассеты предыдущих копированием в свой пакет.

## Как начать кампанию (TGD)

```bash
git fetch origin
git checkout main && git pull
git checkout -b campaign/01-night-pass
mkdir -p campaigns/01-night-pass
```

Дальше: `TASK.md` → чемодан (`campaign-guide.md`, `campaign.schema.json`) →
дизайн-документ → контент. Первый пуш — в течение первых 15 минут работы,
дальше каждые 15 минут.

## Чеклист перед PR

- [ ] задание из `TASK.md` выполнено целиком, пункт за пунктом
- [ ] `design_doc` заполнен и совпадает с содержимым кампании
- [ ] `node __chronicle_ai__/campaign-audit.mjs campaigns/<слаг>` — без ERROR
- [ ] все медиа лежат в `assets/`, ссылки относительные, файлы на месте
- [ ] `attribution` заполнен: источник и лицензия каждого взятого файла
- [ ] ID кампании и id сущностей не менялись
- [ ] квоты изображений и озвучки отработаны осмысленно
- [ ] тема не ломает читаемость системных окон (проверено)
- [ ] `tools/` и `TASK.md` не попали в релизную сборку
- [ ] блок `cf-feedback` добавлен в описание PR (пустой массив, если
      претензий к движку нет)

## Коммуникация

- **Notion** — общий слой для всех ролей: карточка каждой кампании (этап,
  ветка, папка, владелец), форма «Запрос» (вопрос → адресат → ответ), база
  «Пробелы чемодана» (чего не хватило в гайде и схеме; ведёт TD), журнал
  решений.
- **Эстафету передаёт Координатор** — он же маршрутизирует запросы между
  ролями и эскалирует спорное мастерам.
- Каждый ход агент заканчивает статус-блоком: *сделано / артефакты (ветка,
  коммит) / блокеры / запросы / что дальше*.
- Вопросы по движку — только через Notion: TD отвечает и фиксирует, был ли
  это пробел чемодана.
