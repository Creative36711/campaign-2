# Chronicle Forge — цех кампаний

Репозиторий производства **пяти полноценных мини-кампаний** для движка
**Chronicle Forge**. Движок закрыт и здесь не лежит: контент полностью
отделён от движка. Каждая кампания — самостоятельный пакет
(`campaign.json`, `world.json`, `manifest.json`, модули и медиа) и попадает
в `main` только после полного ревью.

## Роли и доступы

| Роль | Зона ответственности | Ветка и что пишет в GitHub |
| --- | --- | --- |
| **Producer** | продукт целиком: очередь, приёмка, контроль релиза | своя ветка; коммитит только каркас репозитория |
| **Technical Game Designer ×5** (TGD-1 … TGD-5) | одна кампания целиком: документ → контент → медиа → самоаудит → PR | своя ветка; коммитит только папку своей кампании |
| **QA Engineer** | аудит кампаний: структура, ссылки, баланс, тексты, логика | читает все ветки; в GitHub не коммитит |
| **Technical Director** (TD) | связка с движком: задание и ID кампании, проверка запуска, апрув, отчёт о пробелах | закрытый контур движка; здесь — только чтение и вердикты |
| **Координатор** | эстафета между ролями, очередь, маршрутизация вопросов, эскалации | оба репозитория, Notion; в GitHub не коммитит |
| **Мастер (владелец)** | `main` и корень репозитория, мерж веток, приёмка результата | полный доступ |

### Ветки и права — главное правило репозитория

- **`main` и корень репозитория — зона мастера.** Ни один агент не пишет в
  `main` и не вливает PR сам: автор открывает PR и оставляет вердикт, вливает
  мастер.
- **Ветка роли создаётся автоматически при старте чата роли.** Создавать и
  переименовывать ветки не нужно; имя своей ветки агент фиксирует в Notion
  (база «Роли»; TGD дополнительно — в карточке кампании).
- **Пишем только в свою ветку.** Чужие ветки — только чтение.
- **Папка кампании живёт внутри ветки TGD:** он создаёт `campaigns/<слаг>/`
  целиком. Producer готовит каркас репозитория своей веткой. Так ветки
  сливаются без конфликтов.
- **TD в этот репозиторий не коммитит.** Его рабочий репозиторий — закрытый
  контур движка; здесь он только читает ветки и оставляет вердикты в
  комментариях к PR. Задание и ID кампании он выдаёт в Notion.
- **Мерж выполняет мастер** — после вердиктов QA и TD и приёмки Producer.

- Роли закреплены: у каждой кампании свой TGD.
- **Одна роль за раз**: в один момент времени работает один агент, эстафету
  передаёт Координатор.
- **Одна кампания за раз**: следующая начинается только после того, как
  предыдущая прошла все гейты и влита в `main`.

## Маршрут кампании

| Этап | Кто | Результат |
| --- | --- | --- |
| 0. Задание | TD | в движке создаётся кампания (ID назначает движок); задание оформляется в Notion — карточка кампании → страница «Задание»: ID, бриф и полный текст `TASK.md` одним блоком кода |
| 1. Дизайн-документ | TGD | первым коммитом — `campaigns/<слаг>/TASK.md` дословно со страницы «Задание»; затем `design_doc` по бланку `__chronicle_ai__/design-template.md` — заполняется **до** контента и обновляется на каждой итерации |
| 2. Производство | TGD | своя ветка, папка `campaigns/<слаг>/`, пакет по гайду, коммит и пуш каждые 15 минут |
| 3. Самоаудит | TGD | `node __chronicle_ai__/campaign-audit.mjs campaigns/<слаг>` — без ERROR |
| 4. PR | TGD | PR в `main` по шаблону, чеклист ниже, блок `cf-feedback` |
| 5. Ревью | QA → TD → Producer | три вердикта в комментариях PR и Notion: аудит / запуск / приёмка. Правки — в ту же ветку |
| 6. Мерж | Мастер | PR влит в `main`; ветка остаётся как история |
| 7. Релиз | TD | сборка `.chronicle` для игроков; сборка остаётся в закрытом контуре |

- **QA** ведёт аудит: структура и ссылки (headless-аудит), баланс по цифрам,
  тексты и логика сюжета, непротиворечивость. Динамический плейтест — не его
  зона. QA в GitHub не коммитит: вердикт живёт в Notion и комментариях к PR.
- **TD** импортирует кампанию из ветки TGD в движок и проходит вступление и
  ключевые маршруты: кампания обязана запускаться и играться без падений. Все
  замечания TD (включая пробелы чемодана) фиксируются в Notion.
- Возврат на доработку — нормальный цикл. Если кругов правок больше двух
  подряд, Координатор эскалирует вопрос мастеру.

## Правила (обязательные)

1. **ID кампании не создаётся агентом.** ID назначает движок; он выдаётся в
   задании (Notion) и живёт в `TASK.md`. Не придумывать, не менять, не
   переиспользовать id сущностей: «устаревшее» удаляется и создаётся заново.
2. **Интернет доступен.** GitHub и npm работают: инструменты можно ставить,
   медиа — скачивать. У каждого взятого файла — источник и лицензия;
   выдуманные права недопустимы. Зависимости в репозиторий не коммитим
   (`node_modules` в `.gitignore`).
3. **Коммит и пуш каждые 15 минут** реального времени: песочница
   сбрасывается, незапушенное теряется. Инструменты разработки храни в папке
   кампании (`tools/`) и пушь вместе с ней.
4. **Контент отделён от движка.** Файлы движка не редактируются и не
   копируются сюда. Механики не выдумываются: чего нет в гайде — в блок
   `cf-feedback`, а не «через флаги».
5. **Медиа — только файлами внутри пакета**, относительные пути. Важный
   контент не живёт по временной внешней ссылке.
6. **Лицензии:** у каждого взятого файла — источник и лицензия в
   `attribution` кампании. Права не выдумываются.
7. **Тексты на русском, id — латиницей** с префиксом секции (`scene_`,
   `npc_`, `item_`, `quest_`…). ID кампании — только из задания.
8. **Системный интерфейс не трогаем**: надписи кнопок и состав меню меняет
   только движок; кампания настраивает `title`, `description` и данные темы
   по гайду.
9. **`main` и корень не трогаем.** Весь вклад — в свою ветку. PR открывает
   автор, вливает мастер.
10. **`TASK.md` — дословная копия задания.** Текст берётся одним блоком кода
    со страницы «Задание» (карточка кампании в Notion) и коммитится без
    правок. TD файлы в репозиторий не кладёт — это делается первым коммитом
    TGD.

## Медиа и квоты

- **Квоты песочницы: 10 изображений и 10 озвучек за ход.** Ход не
  закрывается, пока квота не отработана, если генерировать есть что;
  генерация ради генерации запрещена.
- **Графика** — сгенерированные изображения. Прозрачные роли (эмблема меню,
  спрайты сцен, фигурки боя) — PNG с альфа-каналом; хромакей —
  `cutout-chromakey.py`, результат обязательно осмотреть глазами.
- **Озвучка** — реальный голос: интро, катсцены, ключевые реплики.
- **Музыка и звуки** — только реальные файлы: из `library/` или скачанные
  самостоятельно (источник и лицензия — в `CREDITS.md` и `attribution`).
  Синтезированные заглушки не подставляем; если нужного звука нет — запрос,
  а не подмена.
- Порядок работы по пирамиде приоритетов: критический каркас → атмосфера →
  сюжет → полировка.
